# pi-session-memory — Memory-Architecture Inspection
Source: https://github.com/shengxiao20/pi-session-memory

## 1. ARCHITECTURE

Pure **transcript-index** model: a raw-turn search index over JSONL transcripts (Pi, Claude Code, Codex) — no summarizer, no vector store, no knowledge graph. Backing store is **node:sqlite** (`DatabaseSync`) at `~/.pi/agent/memory.db` (env override `MEMORY_DB_PATH`), WAL mode (`src/db.ts:4-34`). Schema is three tables: `sessions` (session_id, source pi|claude|codex, cwd, started_at, model_id, jsonl_path), `turns` (turn_id, session_id, turn_index, ts, user_text, reply_text, tool_names, user_message_id), and `source_files` (jsonl_path, size, mtime_ms, sha256, parser_version) for sync idempotency (`src/db.ts:6-16`). The "record" is `TurnRow` (`src/db.ts:45`): `{ turn_id, session_id, turn_index, ts, user_text, reply_text, tool_names, user_message_id }` — verbatim user + concatenated assistant text, never distilled. Migration function `_migrate` actively DROPs earlier `memories`/`memory_sources`/`cache_migration_audit` tables — it deliberately regressed from a summary-memory design to raw history only (`src/db.ts:38-52`). A whole JSONL file is replaced atomically per file via `replaceSourceFile` (BEGIN/DELETE/INSERT/COMMIT, `src/db.ts:74-94`).

## 2. CAPTURE

Two paths. (a) Live: `pi.on("agent_settled", ...)` → `writeTurn(ctx)` (`extensions/index.ts:33-35`, `src/writer.ts:8-51`) — every settled agent turn writes the latest user request + all assistant text/tool-call names up to the next user message, keyed `turn_id = "pi:<sessionId>:<userEntry.id>"`. (b) Index sync: `pi.on("session_start")` → `syncChangedHistory()` (`extensions/index.ts:20`, `src/backfill.ts:65`) which rescans source dirs; a file is skipped unless size/mtime changed, then sha256-verified; parser upgrades force one reparse (`src/backfill.ts:98-105`). Idempotency: `INSERT OR IGNORE` on deterministic turn_id (crash-replay safe), sha256 in `source_files`, per-file transactional replace. Capture is session-scoped by construction: every turn row is bound to `session_id = "pi:<sessionId>"` plus stored CWD — no cross-session aggregation happens at write time. Explicit user command (`backfill_memory` tool / menu action) triggers full rescan.

## 3. RETRIEVAL

Model-invoked only, **never automatic injection** (README: "results ... are never automatically injected into model context"; no prompt section is registered). Tools: `recall_memory` (2–8 literal bilingual topic entities, optional sources/cwd/after/before/`question`), `recall_project_memory` (project name matched against stored session CWD dir names, then same entity search inside those sessions), `fetch_session` (read-only turn-range expansion), `review_jev_filtered` (audit filter false-negatives) (`extensions/index.ts:43-172`). Ranking is literal SQL substring scoring: per-entity `instr(lower(user_text || ' ' || reply_text))` hits summed, `ORDER BY score DESC, ts DESC`, LIMIT `recallLimit` (config, required positive int, default 20) (`src/retriever.ts:14-33`). Optional semantic re-rank: local **Jev** (`@typesafe-ai/sdk` `noul` relevance, threshold 0.5) filters keyword false-positives against the full user question, segmented at ≤1024 tokens (`src/jev-filter.ts:5-11`). What reaches context = the tool result text (≤recallLimit turns' full user+reply text; no hard byte cap) — size is bounded only by recallLimit.

## 4. STATE + LIFECYCLE

Everything persists across sessions — raw turns are kept **indefinitely; there is NO decay, TTL, forgetting, compaction, or pruning mechanism anywhere** (special-attention answer). Only deletion is manual: "Deleting that database removes only the index; restarting Pi rebuilds it from local source JSONL" (README), i.e. the transcripts are the durable source of truth and the DB is a rebuildable derived index. Schema versioning is ad-hoc column-add `ALTER TABLE` migration + `parser_version` per source file (`src/db.ts:38-52`, `src/backfill.ts`). Session boundaries: the live writer stops a turn at the next user message (`src/writer.ts:20-22`); the Jev runtime is deliberately session-scoped — started at `session_start`, hard-stopped at `session_shutdown`, and latches "unavailable" for the rest of the session on first failure (`src/jev-runtime.ts:11-36`, `extensions/index.ts:36`); model choice is pinned per session (cannot switch mid-session, `src/jev-runtime.ts:20`).

## 5. SEAM SURFACE

Registers: 7 tools (migrate_project_sessions, recall_memory, recall_project_memory, review_jev_filtered, fetch_session, get_memory_stats, backfill_memory — each with `promptSnippet` behavioral conditioning), 1 command `/pi-session-memory` (folded UI menu: help/whats-new/status/recall/import/migrate), and 3 hooks (`session_start` sync+jev-ready notify, `agent_settled` write, `session_shutdown` jev kill) (`extensions/index.ts:18-39,43-289`). Host-facing human surface: `ctx.ui.notify` toasts (sync stats, jev readiness, errors), the menu, and the `get_memory_stats` tool. **Nothing maps to a durable per-record doc-family**: records are derived indexes of external transcripts (the transcripts themselves live outside the extension), so the doc-family seam fits the *session/turn metadata* (session_id, cwd, ts) at best; the index itself is private storage that is legitimately rebuildable. No statusline/panel widget.

## 6. EXTERNAL DEPENDENCIES

Core is fully offline: node:sqlite (stdlib), node:crypto, fs only — zero embedding models, zero API keys. Optional: local **Ollama** at `http://127.0.0.1:11434` (spawned if unhealthy, min version 0.35.0) running one of three Jev decision models `nimble`/`tev1:4b`/`tev1:0.8b` (`src/jev-runtime.ts:5-8`, `src/config.ts:3`). Jev failure degrades gracefully to literal recall. Reads sibling-agent transcript dirs (Claude Code, Codex) from disk. No network services.

## 7. VERDICT

(a) **~25%** — the extension's essence (rebuildable full-transcript SQLite index + model-invoked search) is orthogonal to durable per-record doc-families; only session metadata (cwd, timestamps, source) would map to a doc-family, and its UI need is a single stats readout, not a panel.
(b) **"capture-boundary hook"** — a host hook firing at turn/settle boundaries with the finalized (user, assistant, tool-names) turn tuple, which no existing approvals/interactions/ambient primitive provides (they record human decisions, not conversation turns); secondarily, an explicit "derived/rebuildable index, not source-of-truth" state class for the seam's durability contract.
