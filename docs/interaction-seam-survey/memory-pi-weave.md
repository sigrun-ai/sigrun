# pi-weave — Memory-Architecture Inspection
Source: https://github.com/EranYonai/pi-weave

## 1. ARCHITECTURE
Hybrid: **plain-Markdown note vault (human-curated) + derived, machine-generated knowledge workspace**. Two scopes: (a) a persistent vault of Markdown notes at `~/.okf/notes/` (`PI_WEAVE_VAULT` override) — the durable "memory"; (b) a repo-scoped derived index under `<repo>/.okf/` (file summaries, structural index) explicitly treated as disposable cache, not source of truth (README "Repository knowledge"). No vector store, no embeddings, no database — the store is filesystem Markdown + JSON sidecars. Records: `Note { slug; body; title; created; updated; tags[]; source: "human"|"agent"|"generated"; frontMatter?: rawLines }` (`src/core/types.ts:21-56`), with a provenance field (`NoteSource`, types.ts:9) and a lossless front-matter passthrough (unknown YAML keys replayed byte-identical, types.ts:33-55). A `NoteSearchHit { summary, score, snippet }` is the retrieval record (types.ts:73-77).

"Weaving" vs plain summarization: capture is NOT LLM-rewritten memory. The note keeps a **verbatim `## Raw` tail** (timestamped fenced blocks, "NEVER edit below this line") plus a structured summary regenerated above it (README, "Think out loud"; `formatRawAppend`). So the model organizes, but the raw human words are preserved immutably — the "weave" is the continuous re-structuring of a growing note rather than one-shot summarization.

Graph structure: YES, explicitly. `src/core/graph/` builds a deterministic `GraphModel` over notes + repo: `GraphNode{ id, kind, label, provenance, detail }` with kinds vault/note/repository/module/package/entryPoint/gitState/external/file and `GraphEdge{ source, target, kind }` with kinds `contains | anchored-at | links-to | mentions` (`src/core/graph/model.ts:10-48`; builder `graph/build.ts` is pure, byte-stable via sha256 content digests). `[[wiki-links]]` are first-class: link extraction (`graph/wikilinks.ts`), backlink-preserving rename, and deterministic stale-link repair resolving by exact slug → unique basename → unique title, ambiguity never guessed (`src/core/links/repair.ts`, README "Keeping the vault connected"). A `suggest` action proposes unlinked-but-related notes (noteTool.ts:31).

## 2. CAPTURE
**No automatic per-turn capture.** All writes are explicit model actions through the `weave_note` tool (actions list/get/add/append/finalize/search/links/suggest, `src/pi/tools/noteTool.ts:9-56`) or human edits in the browser workspace. The only LLM-distilled capture is **opt-in commands**: `/weave-scan` (summarize changed repo files) and `/weave-scan sessions [dir]` — which reads bounded transcript files, hashes each while reading so unchanged sessions are skipped (`src/core/sessions.ts:4`), and writes generated memory notes under `~/.okf/notes/sessions/` via the session model (`src/pi/sessionScan.ts:26-31`, `SESSION_SCAN_SYSTEM_PROMPT` at `src/core/sessions.ts:51`). Deep scans run in temporary child sessions with tools denied (README). Hooks registered are lifecycle-only, not capture: `session_start`, `agent_start` (turn boundary → `recallTrail.beginTurn()`), `agent_end` (status refresh), `session_shutdown` (web teardown) (`src/pi/index.ts:94-119`). Idempotency: content-hash skip for scans (sessions.ts hashing; `GitState.changedHashes` anchors the repo index staleness, types.ts:84-99). Capture is NOT tied to a conversation/session id — notes are vault-global; provenance is a coarse human/agent/generated tag, not session identity. Every note revision is appended to `<vault>/history/<slug>.jsonl` (append-only, one JSON per revision, `src/core/history.ts:13-66`), disableable via `okf.json "history": false`.

## 3. RETRIEVAL
Model-invoked tool `weave_note action=search` (query param; ranked slug/title/tags/body matches **plus linked, tagged, and lexically related notes** — graph-augmented lexical ranking, no embeddings; `src/core/noteAction.ts:26`); returns the full note when a single result resolves (tool promptGuidelines discourage refetch loops, noteTool.ts:24-25). There is **no automatic prompt injection** — the harness does not inject memory; the model must call the tool (guided by `promptSnippet`/`promptGuidelines` and bundled skills `weave-notepad`, `weave-explore`). Context size is bounded by search `limit` and full-body inclusion only for top hits (`COMPLETE_BODY_RESULTS`, noteAction.ts:122-150). Recall is observable: the `RecallTrail` buffer records every searched/read/wrote event in-order with turn numbers (`src/core/trail.ts:14-40`, capacity 200, in-memory only) surfaced in the status line ("used N notes", index.ts:47-48) and the browser Context card.

## 4. STATE + LIFECYCLE
Durable: the vault (Markdown notes + front matter), `<vault>/history/*.jsonl` revision logs, repo index under `.okf/` (cache; git-staleness-anchored), browser workspace layout/preferences (per vault+repo, survive updates). In-memory only: the recall trail (deliberately session presentation, trail.ts:9-13), in-flight scan state, unsaved browser drafts. Session boundaries are handled by explicit re-bridging: the agent searches the vault to "bring knowledge forward"; `/weave-scan sessions` is the bulk session→memory distiller. No decay/forgetting mechanism; growth is unbounded user-curated Markdown. No schema versioning of notes (lossless front-matter passthrough absorbs drift); `GitState.changedHashes` documents reader tolerance for older indexes (types.ts:94-95).

## 5. SEAM SURFACE
Registered with pi (`src/pi/index.ts`): tools `weave_note` + `weave_repo`; commands `/weave`, `/weave-view`, `/weave-scan`, `/weave-scan-cancel`; lifecycle hooks (session_start/agent_start/agent_end/session_shutdown); statusline slot "weave" with activity indicator, note-usage count, and web port (`c.ui.setStatus`, index.ts:36-92). Host-facing human surface: a full **browser workspace** (loopback-bound, per-session token HTTP server + SSE + file watcher, `src/web/server/`) with graph view that lights up notes the agent touched, note editor, history playback slider, and manual vault ZIP backup — plus `/weave` dashboard text. Durable per-record doc-family fit is excellent: notes ARE durable documents (Markdown + front matter + JSONL history), already carrying provenance tags and revision history — the closest existing analog to sigrun's doc-family record shape. The recall trail is the "ambient/interaction record" analog (session-scoped, presentation-only).

## 6. EXTERNAL DEPENDENCIES
None at runtime beyond the harness: pure local filesystem + Node 20.13+; zod is the only direct runtime dep (README "Development"). LLM calls (deep/session scans, dictation structuring) use the session's already-configured model via `modelRegistry` — no extra API keys, no embedding models, no external services. Fully offline-capable for all vault operations; scans consume model quota. Browser workspace binds loopback only with a per-session token.

## 7. VERDICT
(a) **~85%.** Its core state is already durable Markdown documents with front matter, provenance, JSONL revision history, and a derived graph — a doc-family + generic panel seam covers the vault nearly natively; what falls outside is the session-scoped recall trail (in-memory ambient buffer), the repo-index cache, and the live SSE/web workspace, which a static generic panel would only partially render.
(b) **A "derived-artifact cache" primitive** — per-scope, rebuildable machine-generated indexes anchored to source content hashes (GitState/content digests with staleness reporting), cleanly separated from durable records; approvals/interactions/ambient have no notion of disposable derived views built from durable docs. Secondary motivator: deterministic bidirectional link resolution/repair over a doc family (`links/repair.ts`), which generic doc-families don't yet offer.

**Special attention findings:** weaving ≠ summarization — the invariant is a never-edited verbatim `## Raw` tail under a model-maintained structured summary, so capture preserves raw provenance while presentation is continuously reorganized. Graph structure is real and central: typed nodes/edges (contains/anchored-at/links-to/mentions) spanning vault notes AND repository structure, byte-deterministic builds, wiki-link graph with backlink rewrite and non-guessing link repair.
