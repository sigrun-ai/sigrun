# Sigrun 0.1 Acceptance Test Plan (pi parity)

The manual and scripted acceptance run for the 0.1 release. It's run once per deployment after `2026-10-21-release-0.1.md` Phase 2:

- **L** — workstation, installed with `npm i -g @sigrun/sigrun`, with a fresh `SIGRUN_CONFIG_DIR`;
- **D** — Docker, using `docker/docker-compose.yaml` with the published image;
- **K** — Kubernetes, using the homelab Flux HelmRelease with the published chart, behind the real ingress.

Channels: **W** webui, **T** TUI (`sigrun` / `sigrun attach`), **A** HTTP API (curl). A cell marked `·` is not applicable.

**What pi parity means here:** what `pi` 1.3.0 gives a user out of the box, as specified in `docs/superpowers/specs/2026-10-12-sigrun-pi-parity.md`:
- tools, skills, MCP, compaction, sessions, auth readiness, slash commands and settings;
- plus pi's built-in extensions, codemode and tool search.

Sigrun-only features shipped in 0.1 (accounts and sharing, jobs, the webui, deployment, operations) are tested in the same pass, because friends and family will meet them on day one.

## How to run

- Record each case as pass, fail or blocked, with a note, in a copy of this file named `acceptance-0.1-<L|D|K>-<date>.md`. Don't edit the plan itself.
- **Provider for the run:** `@sigrun/provider-ollama` against a reachable Ollama, plus one hosted provider. Any of `@sigrun/provider-opencode`, `-pareto` or `-bifrost` will do.
- **Models:** a tool-capable model for the C–I sections, and a vision model for D5.
- **Fixtures** (create once, in the workspace):
  - a git repo `demo/` with a `.gitignore` ignoring `build/`;
  - `demo/build/out.txt`, `demo/src/a.ts`, and a 1×1 PNG `demo/pixel.png`;
  - a skill `skills/greet/SKILL.md` (frontmatter `name: greet`, `description: say hello in Norwegian`) with `skills/greet/references/words.md`;
  - the MCP "everything" test server (`npx -y @modelcontextprotocol/server-everything`) for F.
- **A failure blocks release** unless it's in "Known gaps" below, or you explicitly waive it in the run file.

## Known gaps vs pi (decide before release: ship as gaps, or add tasks)

1. **`/skill:name`** — not in the slash catalog (`src/server/commands.ts` scope note). Skills load through `load_skill`, or through `read` on the listed path.
2. **Prompt templates** — not implemented (pi parity spec, "Missing from pi's core surface" item 1).
3. **`/login` / `/logout`** — excluded by design: credentials go through the settings credential routes, not the chat surface.
