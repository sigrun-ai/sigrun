**Architecture:**
- **Packages** (all at `0.1.0`, exact version pins inside the family):

  | npm name | repo | role |
  |---|---|---|
  | `@sigrun/shared` | `sigrun` (`shared/`) | wire types, zero dependencies |
  | `@sigrun/tui` | `sigrun` (`tui/`) | terminal client, optional dependency of core |

  | `@sigrun/ext-memory-markdown` | `sigrun-ext-memory-markdown` | optional extension |
  | `@sigrun/provider-ollama`, `-opencode`, `-pareto`, `-bifrost` | `sigrun-ollama` etc. | provider extensions |

- **Built-ins mirror pi 1.3.0.**
  - Codemode, MCP and tool search are core dependencies, loaded as built-in extensions unless disabled in settings.

- **Publishing is CI-driven** (GitHub Actions, npm trusted publishing with provenance, GHCR for the image and the OCI Helm chart). The first npm publish of each package is manual **(you)**, because trusted publishing can only be configured on a package that already exists.

### Task 2c: `/skill:name` and prompt templates (pi parity)

**Finding:** the last two pi parity gaps (pi parity spec, slice 7 and "Missing from pi's core surface" item 1). `src/server/commands.ts` defers `/skill:name`, and prompt templates don't exist. Pi 1.3.0's behaviour, which sigrun matches:

- **`/skill:name [args]`** expands, before the text reaches the agent, to
  ```text
  <skill name="NAME" location="PATH">
  References are relative to DIR.

  BODY (SKILL.md with frontmatter stripped)
  </skill>

  ARGS
  ```
  (the blank line and `ARGS` only when arguments were given). An unknown skill passes through unchanged. `disable-model-invocation: true` skills are hidden from the model's skill list but still usable through `/skill:name`. Every skill appears in the `/` menu as `skill:<name>` with its description.
- **Prompt templates** are Markdown files whose filename is the command (`review.md` → `/review`). Frontmatter `description` (else the first non-empty line) and optional `argument-hint`. Arguments are shell-quoted (`/review "API compatibility"` is one argument). Substitutions: `$1`, `$2`, …; `$@` and `$ARGUMENTS` (all, space-joined); `${1:-default}`; `${@:-default}`; `${@:N}`; `${@:N:L}`.

**Decisions (flag in review):**

- **Expansion is server-side, at admission** (in `submitOp`, before content-part resolution), so the webui, the TUI, `host.conversations.submit` and the HTTP API all behave the same, and job prompts can use templates. A `/name` that is a core or extension command keeps its existing meaning; expansion applies only to `skill:*` and template names, and a template whose name collides with a core or extension command is skipped with a warning.
- **The transcript shows what the user typed.** The admitted input is the expanded text (that is what the model gets); the user entry carries `entry: {kind: "sigrun.user.expanded", data: {typed, command}}` (pi-durable `InputEntry`), and both channels render `typed` with a small "expanded from /review" chip that reveals the full text.
- **Template roots, in precedence order** (first wins, like skills): the workspace's `prompts/` directory; `<configDir>/prompts/`; then each installed package's `prompts/` directory (attributed to the extension). Direct `.md` children only.
- **Live:** both lists are re-scanned on each `/v1/commands` request and at each expansion (the skills extension already reads its roots live), so no reload command is needed.

**Files:**
- Create: `src/commands/expand.ts` (`parseCommandArgs`, `expandTemplate`, `expandSkillCommand`, `expandInput`), `src/commands/templates.ts` (discovery across the three roots)
- Modify: `src/server/conversation-ops.ts` (`submitOp` calls `expandInput` on text-only inputs that start with `/`), `src/server/commands.ts` + `shared/src/commands.ts` (catalog entries for skills and templates: `SlashCommand.kind?: "endpoint" | "expand"`; `endpoint` optional when `kind` is `"expand"`), `src/skills/index.ts` (export a live `listSkills()` for the catalog and expansion, including model-hidden skills), `src/harness/boot.ts` (wire template roots), `src/jobs/fire.ts` (prompt actions expand too)
